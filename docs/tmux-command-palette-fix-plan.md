# tmux 커맨드 팔레트 레이아웃 및 정렬 개선 계획

## 1. 현재 문제점 분석

### ① 단축키 목록 정렬 부재
- **현상**: `Ctrl+a` (Prefix) 조합 키와 `[Root]` (단독 단축키)가 임의의 순서로 마구 뒤섞여 나옵니다.
- **원인**: 단순히 `sort -u`로 정렬하여 아스키 순으로 문자열 정렬이 일어났기 때문입니다.

### ② 이모지 혼용 및 컬럼 정렬 깨짐
- **현상**: 이모지(`🎨`, `➡️`)의 디스플레이 가로 폭(Multi-byte Width)이 일반 영문자보다 크기 때문에, 줄 맞춤(`printf` 정렬) 시 세로 줄 정렬이 완전히 무너집니다.
- **원인**: `fzf`가 여러 필드(`|` 구분자)를 다룰 때 자동으로 맞추는 탭 너비가 이모지 멀티바이트 폭과 일치하지 않아 칸이 어긋나게 렌더링됩니다.

### ③ 팝업창 깨짐 및 답답한 느낌
- **현상**: 팝업 크기가 커진 상태에서 `fzf` 고유의 테두리(border)와 tmux 팝업 자체의 테두리가 겹쳐 렌더링되거나 화면이 찌그러져 보입니다.
- **원인**: 팝업 내에서 `fzf`가 유동적인 높이로 레이아웃을 계산하다가 tmux popup 테두리와 충돌을 일으키기 때문입니다.

---

## 2. 구체적인 개선 및 정제 방안

### ① 그룹화 및 정렬 체계 개선
- **핵심 단축키 최상단 배치**: 우리가 직접 정의하고 관리하는 핵심 단축키(Notes 설명이 한글로 명시된 키)를 최상단(우선순위 1)에 배치합니다.
- **Prefix 그룹 분리**: `[Ctrl+a]` 키바인딩을 먼저 묶어서 알파벳 순으로 정렬하고, `[Root]` 단독 키들을 그 하단에 묶어 정렬하여 사용자가 인지하기 쉽게 만듭니다.

### ② 컬럼 정렬(줄 맞춤) 방식 개선
- **이모지 폭 보정**: 이모지나 한글은 문자 수 기준이 아닌 **바이트/비주얼 너비(Visual Width)**를 기준으로 패딩(Padding)을 채워주거나, **`fzf` 자체의 Tabstop 옵션**을 조율합니다.
- **더 깔끔한 UI 제안**: fzf 화면에는 오직 **`[단축키]  설명`**만 깔끔하게 정렬하여 한 행으로 노출하고, 복잡한 실제 명령어(`tmux cmd...`)는 우측 또는 하단의 **Preview/Info 영역**으로 완전히 격리하여 시각적 노이즈를 제거합니다.

```
┌────────────────────────────────────────────────────────┐
│ ⌨️ 단축키 검색 및 실행>                                │
│ > [Ctrl+a T]      🎨 테마 피커 실행                     │
│   [Ctrl+a s]      🗂️ 세션 런처 사이드바 토글             │
│   [Ctrl+a |]      ✂️ 작업 영역 가로 분할                │
│   [Tab]           ➡️ 다음 윈도우로 이동                 │
├────────────────────────────────────────────────────────┤
│ [실제 명령어] display-popup -E -w 60% -h 55% ...       │ (하단 프리뷰로 격리)
└────────────────────────────────────────────────────────┘
```

### ③ 팝업 레이아웃 및 fzf 옵션 최적화
- **fzf 테두리 제거**: 팝업과 겹치지 않도록 `--no-border` 또는 `--margin=1` 옵션을 적용합니다.
- **크기 및 스크롤 고정**: `--height=100%` 및 `--layout=reverse`를 강제하여 팝업 내부 레이아웃을 꽉 채우고 깨짐을 방지합니다.
- **이모지 최적화 폰트/너비 보정**: bash 내부에서 문자의 가시 폭을 계산하여 정확한 스페이스 패딩을 주입하는 정렬 래퍼 함수(`align_columns`)를 도입합니다.

## 3. 구현 방법론 (스크립트 세부 가공)

```bash
# 디스플레이 너비(Visual Width)를 감안한 탭 정렬 함수 예시
pad_width() {
    local str="$1"
    local target_len="$2"
    # 문자열 내 멀티바이트(한글/이모지)의 실제 가시 너비 계산
    # (awk를 사용해 각 문자의 스크린 가로 폭을 계산하고 부족한 만큼 공백 추가)
    echo "$str" | awk -v max="$target_len" '
    BEGIN { FS="" }
    {
        w = 0
        for (i=1; i<=NF; i++) {
            # 한글 및 이모지는 2칸, 나머지는 1칸으로 가산
            if ($i ~ /[ㄱ-ㅎㅏ-ㅣ가-힣]/ || ord($i) > 127) w += 2
            else w += 1
        }
        pad = max - w
        printf "%s", $0
        for (i=1; i<=pad; i++) printf " "
    }'
}
```

## 4. 진행 절차 제안

1. **의견 수렴**: 위 레이아웃 디자인(설명 위주 목록화 + 하단 실제 명령어 프리뷰 격리) 및 정렬 방향성에 대해 의견 조율.
2. **코드 반영**: `scripts/tmux-command-palette`에 패딩 보정 및 fzf 테마/옵션 정밀 튜닝 코드 적용.
3. **tmux.conf 튜닝**: 팝업창 크기와 테두리 조화성을 맞추기 위해 바인딩 매개변수 미세 조정.
4. **로컬 테스트 및 배포**: `install.sh` 연동 검증 후 최종 commit & push.
