# v0.6.7 Sidebar 10-Session Sequential Navigation

Scenario: isolated tmux socket, attached urxvt client, 100x30 geometry, ten sessions (`nav-01` through `nav-10`). A sidebar is created in `nav-01`; nine physical `j` keypresses select sessions from top to bottom. Each step waits for the normalized cursor row and records step and cumulative time.

Command:

```sh
bash tests/profile-sidebar-navigation.sh
```

Polling interval: 10ms. The user tmux server is never used.

| 1 | nav-02 | 69 | 57 | 72 | 69 |

| 8 | nav-09 | 57 | 53 | 54 | 54 |
| 9 | nav-10 | 54 | 55 | 53 | 54 |

Final cumulative time: 1151ms, 1122ms, and 1133ms; median 1133ms.

Final cursor invariant: exactly one cursor, target `nav-10`, PASS on all runs.

## Findings

- Normal sequential movement is approximately 52-72ms per key under the current capture-pane observer.
- One step per run shows a 573-584ms outlier, at different positions (step 2 in runs 1 and 3, step 4 in run 2).
- The outlier is consistent with periodic sidebar state refresh/scheduler contention rather than session-count growth alone.
- The scenario exposed and fixed a missing `session_command_signature_from_tmux` helper, which was called by the selected-session fallback path when the ten-session run reached the periodic refresh boundary.
