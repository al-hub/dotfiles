# v0.6.8 Reproduction Performance Report

Profile: `tests/profile-isolated-sidebar-reproduction.sh`  
Baseline: v0.6.7 auto/reproduction profiles  
Environment: isolated tmux socket, attached URxvt, repository `dotfiles/tmux.conf`, temporary HOME, `100x30`, tmux 3.6.  
Samples: 3 auto/reproduction comparison runs, 10-run smoke, and 30 reproduction final runs; the final sample contains 570 navigation steps.

## Implementation under test

- Added selection trace IDs and `selection.update/render` timing events to the launcher.
- Added optional `PROFILE_TRACE=true` internal trace mode.
- Added optional `PROFILE_PIPE_OBSERVER=true` output-observer latency mode.
- Batched animation, age-cell, and animation-state row writes to reduce repeated tty writes.
- Deferred age/force-refresh/state maintenance when a key is present so selection rendering gets priority.
- Separated `send-keys` dispatch time from pane output observation time.
- Preserved v0.6.7 cursor, lifecycle, sidebar count, client alignment, archive, and restore invariants.

## Internal trace result

Trace-enabled diagnostic smoke samples recorded internal selection render durations between approximately 1 and 7ms, including when external output observation saw a 1.1~1.2 second delay. This separates the launcher selection calculation from the delayed tty/tmux output observation path. Trace mode is not used for CPU promotion measurements because it adds file I/O overhead.

## Interpretation

1. Output batching alone did not remove the long-tail delay; key-path maintenance deferral removed it in the current three-run sample.
2. Internal selection rendering and send dispatch remain fast, but periodic refresh collision still produces a long-tail output delay in 4/570 steps.
3. CPU remains approximately 16~17% at p50 and has a high idle p95, so the ≤8% challenge target remains unresolved.
4. Archive bytes and restore latency remain setup-sensitive because auto and reproduction do not yet share an identical HOME/history fixture.
5. The maintenance deferral improves ordinary navigation but does not fully protect the periodic refresh boundary; that boundary is now the primary product investigation target.
