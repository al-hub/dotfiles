# v0.6.7 Reproduction Sidebar Profile

Script: `tests/profile-isolated-sidebar-reproduction.sh`

Environment: isolated tmux socket, attached URxvt client, repository `dotfiles/tmux.conf`, temporary HOME, `100x30` geometry, tmux 3.6, three runs, 10ms key polling.

This profile follows `docs/reproduction.md`: it discovers the attached client tty, uses `switch-client -c`, sends physical `j`/`k`/`Enter` keys, waits 7 seconds after source stabilization and 2 seconds after Enter, re-discovers the target sidebar, and captures the target grid with `capture-pane -e`.

## Interpretation

1. The clean standard phase follows the guide order: background switch, 7-second stabilization, `j`, `Enter`, 2-second stabilization, target capture. Sidebar setup now uses the same launcher toggle command as `Ctrl+a s` and the repository tmux configuration.
2. The attached-client reproduction path verifies explicit client targeting both in the profile and in the launcher’s Enter switch path, sidebar toggle setup, physical `j`/`Enter` pane input, target pane re-discovery, cursor alignment, and ANSI capture.
3. Reproduction key and session-switch medians were lower than auto in this sample. CPU/RSS were also lower, while archive bytes and restore are setup-sensitive because the profiles use different shell/configuration contexts.
4. `capture-pane -e` produced zero ESC characters in these runs. This is a measured rendering result, not a missing check; the plain-text cursor invariant still passed. A future test should determine whether this reflects tmux capture mode, terminal color negotiation, or the launcher’s current render path.
4. Applying resize to the actively navigated sidebar exposed a transient pane/cursor race during development. The final profile isolates resize on a fresh sidebar, matching the existing auto profile’s independent resize phase. The combined navigation+resize race remains a product investigation item rather than being hidden by the test.
5. A duplicate sidebar title was traced to `mark_sidebar_pane()` targeting the active pane instead of `TMUX_PANE`; this was corrected, and the exact-one-sidebar invariant passed 3/3.

## Remaining deviations

- Physical `Ctrl+a s` injection is not available in the current headless/X environment; setup invokes the binding's `--open-sidebar` launcher command directly.
- The standard phase uses a separate socket and server; the common metric phase runs on a separate fresh server afterward, both with repository tmux configuration.
- Navigation resize remains an independent diagnostic phase; resize during active navigation is not a standard PASS condition.
- Key latency still uses capture polling for compatibility with the existing auto profile; a pipe-observer-only latency comparison remains a follow-up.
- Mouse/focus and actual terminal resize events are not simulated.
- Archive/restore byte and latency differences require a matched HOME/history fixture before they can be treated as product performance differences.

## Next steps

- Run both profiles for a larger sample, preferably 10–30 runs, and classify outlier location and frequency. The current three-run sample includes isolated 1.2-second navigation outliers.
- Add a diagnostic mode that records pane lifecycle events and selection/render timestamps around resize and the outlier step.
- Investigate why `capture-pane -e` reports zero ESC characters while cursor state remains correct.
- Decide whether combined navigation+resize should become a separate explicitly expected lifecycle scenario.
- Keep auto and reproduction metric schemas synchronized before promoting any new version or performance conclusion.
